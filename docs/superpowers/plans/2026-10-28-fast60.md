# Fast60 quality-first benchmark and refinement implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Supervisor owns GPU dispatch, integration and publication. Preserve dirty implementation checkout and other agents' files.

**Goal:** Establish independently measured quality against executed ZED SDK references, then reach stable native 720p metric-depth processing at 60 Hz without hiding quality loss or historical reuse.

**Architecture:** Keep full-resolution original camera RGB and independent two-eye SGM as the internal baseline. The multiresolution matrix and guided refinement are now experimental evidence, not a selected replacement. Build canonical SDK export/replay and an already-rectified native adapter while investigating sparse-to-dense Fast60 on independent development fixtures. Combine full-resolution sparse evidence, coarse stereo and compact local hypotheses; promotion requires common-input full-SGM quality and independent truth at a frozen target. Portable neural inference remains a separately qualified experiment.

**Tech stack:** C++20, pinned Daxa/Slang/Vulkan; Python/OpenCV only for offline calibration/fixtures/evaluation. No CUDA/HIP/ROCm/TensorRT production dependencies.

**Spec:** User's 2026-10-28 SDK comparison amendment captured in [the quality benchmark design](../specs/2026-10-28-zed-quality-benchmark-design.md), the existing Fast60 strategy and parent `2026-10-27-daxa-slang-production.md`; temporal contracts in `../specs/2026-10-28-native-temporal-design.md` remain binding.

## Current decision and next priority

The [refinement evidence](../../fast60-refinement-evidence.md) reports roughly
54.4% correct metric completeness for guided matching versus 95.3% for full SGM
on the same analytic scene. Approximately 8 ms exploratory combined GPU time
does not compensate for that loss. Confidence-floor development ablation reaches
about 69.1% overall but only about 0.52% thin completeness; threshold relaxation
is not a quality fix. Native correctness, independent physical accuracy and live
60 Hz remain separate gates.

**Next execution order:** retain the common-input benchmark and full-SGM baseline;
in parallel, pursue the sparse-to-dense development experiments below on fixed
analytic fixtures. Follow the [benchmark implementation plan](2026-10-28-zed-quality-benchmark.md).
Neither SDK host availability nor VIO blocks portable prototyping, but absent SDK
runs, independent truth, or held-out evaluation cannot pass the corresponding
quality gates or justify promotion.

## Frozen boundaries

- Profiles: rectified1280×720/D128,960×540/D96,640×360/D64, independent Left AND Right, four paths, matched penalties/subpixel/wave32. Original capture bytes/calibration/source RGB remain unchanged. No derived-right promotion.
- Native D96 is admitted already (StereoConfig1…256, dynamic specialized packed shader); qualify it rather than change kernels or silently substitute D128. Existing Python qualification whitelists need explicit tests/extensions.
- Freeze LR tolerance at1pixel and stereo schedule `sequential` for the primary matrix; four independent-reference paths, p1=8/p2=32, subpixel enabled, wave32. Changes require a separately labelled ablation.
- Scale focal lengths and principal-point offsets consistently. Use pixel-centre convention `u_small+0.5=s*(u_full+0.5)`, so `fx'=s*fx`, `cx'=s*(cx+0.5)-0.5` (and y equivalents). Scale projection Tx and disparity offset; preserve metric baseline and original camera models/R1/R2. Reject incompatible aspect/shape choices.
- Recompute maps directly from original calibrated models into the requested rectified grid. Do not rescale already rectified RGB or discard original peripheral colour. Preserve original source dimensions/stride/timestamps and map/model association gates. Existing bilinear remap is the initial measured sampling profile; antialiasing/texture loss is a quality question, not assumed solved.
- Equivalent approximate minimum metric distance follows `Z=fx*b/(d-(cxL-cxR))`; report calibrated profile limits using nominal near `fx*b/((D-1)-cx_offset)` only when that denominator is positive (otherwise unavailable). D128/D96/D64 scaled profiles have approximately, not exactly, equal near range because their integer maximum disparities differ. Never claim D64 full-resolution preserves D128 near-field range. Do not use representative camera focal lengths as actual fixture calibration.
- Primary stereo comparison disables RGB synthesis and temporal guidance. Measure full-resolution output/View cost separately with an explicitly fixed virtual camera, not a silently shrunken output canvas.
- Reduced-resolution depth remains labelled as such. Upsampling does not create independent full-resolution measurements. Strict geometry, validity/confidence/source IDs and observation ages retain their existing meanings.
- Desired processing gate: p99≤15ms with maximum service time, raw samples and frame-age/throughput/queue/drop accounting. Stage budgets6ms coarse/3ms refinement/3ms metric+View plus1–2ms overhead are targets, not predictions or measurements.
- Final live gate: ≥10minutes nominal60Hz, delivered unique frames/gaps/drops/age/queue growth, bounded2–3 slots, actual capture→GPU→consumer with relevant sharing pressure. Camera transport/exposure age is separate from processing service time.
- External SDK reference work is isolated on supported NVIDIA/Ubuntu; its proprietary/CUDA dependencies are not StereoForge runtime dependencies. Record supported modes, installed versions, effective calibration and any fallback. Primary external target is executed `NEURAL_LIGHT`; `NEURAL`/`NEURAL_PLUS` are additional profiles and deprecated `PERFORMANCE` is an availability-checked classical control.
- Preserve raw confidence conventions and separate matching/texture filtering. Compare error-versus-coverage, not equal numeric thresholds. Primary instantaneous quality has temporal stabilization off; temporal-on tests are separate.
- D128 is not the full nominal ZED 2 near-field envelope. Report calibrated supported range and requested0.3–8m completeness separately; shifted/local searches beyond128 are explicit experiments, not silently global D256 or removed truth samples.

## Review focus

- Half-pixel scaling, P2 Tx/cx offsets and original-vs-rectified identity must preserve metric geometry.
- Thin objects/discontinuities and near depth may disappear at coarse resolution; completeness and false accepts must accompany error metrics.
- D96 packing tails and LR handling must match independent scalar/frozen control outputs before timing.
- Lower-grid support and sparse virtual splats must not become unmarked full-resolution depth or inflated coverage.
- Tile/adaptive refinement must reduce candidate AND aggregation work; masked dense recurrences are not a demonstrated saving.

## Task FS — Sparse-to-dense Fast60 research amendment

**Hypothesis:** full-resolution sparse correspondence anchors, coarse stereo and
compact local geometric hypotheses can reduce dense search and aggregation while
preserving independently verified geometry. This is an experiment, not a new
default. Maintain the frozen independent 720p/D128 two-eye SGM reference and the
four stereo ablations; use identical input, calibration, truth support and
configuration identities. Original full-resolution RGB remains available to View.
Before evaluating or tuning each experiment, set provisional numerical development
gates for thin and boundary completeness, near-range completeness and false
acceptance, and fix truth support and partitions. Development data may inform
tuning and final thresholds; freeze those numerical thresholds and the selected
settings before held-out evaluation. No values are asserted here. Missing gates
means no advancement or promotion.

The [prior feasibility study](../../fast60-prior-feasibility-evidence.md) shows
that missing coarse priors and narrow windows exclude thin geometry; partial-prior
relaxation increased false acceptance and a tile fallback could approach dense
work. The [overwrite evidence](../../daxa-sgm-overwrite-evidence.md) separately
reports 35.0–36.2 Hz in short live ROS/Zenoh runs, with changing frames and shared
GPU load. Neither establishes 60 Hz, independent physical accuracy, or a saving
for this proposal. Retain all failed candidates and their masks for comparison.

A separate CPU compact-SGM development comparison on one analytic scene reports
thin-region correct metric completeness of 44.501% left / 45.480% right for
radius-2 constrained intervals versus 60.714% / 62.263% for its full-D control.
False LR accepts among accepted thin-region pixels were 847/2,255 and 668/2,107,
versus 402/2,323 and 384/2,354 in the control. Local-only evidence is
`artifacts/daxa-refinement-20261028/compact-sgm-quality-offline/{r2-v3,full-v3}.json`,
produced by `benchmarks/compact_sgm_quality.py`. Both CPU cases use infinity for
unsupported costs and integer-only selection, unlike the native finite 10000
sentinel and subpixel configuration; they are not native parity, GPU timing, or
physical accuracy evidence. The candidate requires stronger quality and false-match
results before promotion.

- [ ] **FS1 — sparse anchors.** Establish an independent scalar reference and
  deterministic full-resolution grid/FAST point selection plus epipolar Census
  matching for each eye. Compare ORB as an optional offline ablation, not a
  production dependency. Search beyond D128 where calibration admits it; validate
  disparity sign, principal-point offset, image bounds and independent reverse-eye
  evidence. Measure sparse precision/recall, false accepts, support distribution,
  thin-object and boundary recall on fixed truth, including points absent in 360p.
  Unsupported/ambiguous points stay invalid. Explicitly test disparity >127 and
  features absent on thin objects: corners can miss them. Missing anchors require
  bounded fallback or invalid output. Record feature selection and search costs;
  edges alone are not correspondence or metric observations. **Advance** only
  if predeclared anchor coverage and false-accept gates pass on fixed development
  support; otherwise reject the configuration and retain its failures.
- [ ] **FS2 — competing geometric hypotheses.** Combine qualified sparse anchors
  with independent 360p stereo candidates, without pretending upsampling creates
  observations. Fit local disparity planes `d(u,v)=a*u+b*v+c` only with adequate
  support; use boundary-aware region splitting or bounded multiple candidates
  where surfaces compete. Test slanted planes, mixed-depth tiles, occlusions,
  thin foreground and textureless areas. Track the evidence and source identities
  behind each hypothesis; interpolated geometry is estimated until independently
  verified against current stereo imagery. Evaluate current image costs separately
  in each eye and retain their source identities. A right hypothesis seeded by
  the left is correlated and is not independent evidence by default. Scores are
  not calibrated uncertainty. **Advance** only if predeclared thin, boundary, near and
  false-accept development gates pass, including missing-anchor cases; otherwise
  reject the configuration, preserving masks and work counts.
- [ ] **FS3 — compact full-resolution verification and recovery.** Evaluate
  actual compact 8/16/32-candidate buckets, shifted local ranges and a bounded
  broad-search fallback on both eyes. Compare full-frame narrow matching with
  selective tile/edge recovery and include work from halos, support extraction,
  compaction, regularization, reverse-eye verification and fallback. Report actual
  allocated/processed candidate and aggregation slots, bytes, GPU time and counts;
  masking a dense SGM recurrence is not work reduction. Explicitly measure how
  work/quality changes with risk-region fraction; do not infer SGM equivalence from
  a cheaper local verifier. Unverified or incompatible surfaces remain invalid.
  **Advance** only when predeclared development quality gates pass and measured total
  work and matched latency improve against the independent full-SGM control;
  otherwise reject the configuration and retain the full baseline.
- [ ] **FS4 — known-motion temporal extension.** After static gates, test optional
  pose-warped candidates under known timestamped motion before estimated motion.
  Verify reprojection, occlusions, moving objects, reset/refresh and disocclusions;
  preserve original observation IDs, age and provenance, and prevent correlated
  history being counted as independent fresh stereo. VIO/SLAM is an external
  optional motion provider, not a prerequisite for FS1–FS3 or a replacement for
  tracking qualification. Benchmark temporal-off/on as separate configurations.
- [ ] **FS5 — qualification.** On identical development scenes report valid and
  correct metric completeness on fixed truth support, relative/absolute error,
  error-versus-coverage, false accepted matches, thin recall, boundary quality and
  range bins; compare full SGM, coarse-only, guided, anchors-only and combinations.
  Include calibrated near-field coverage down to the requested 0.3 m where the
  physical camera and truth support it, with shifted-range and support limits
  explicit. Evaluate fixed 0.3–8 m truth support, separately accounting for
  visibility, occlusions, out-of-image points and camera-supported range; never
  hide unsupported near depth by removing it from requested-range reporting.
  Set provisional numerical gates before each experiment and freeze development-
  derived final thresholds and selected settings before held-out analytic and
  independently measured physical scenes;
  unavailable truth remains unknown. Promotion requires passing those held-out
  physical scenes as well as the other gates.
  Compare an actually executed SDK on common frames only where available and
  authorized; user authorization is not evidence of a reviewed vendor grant.
  Record applicable terms or written permission and its scope separately; see
  [license evaluation](../../license-evaluation.md). SDK agreement is not ground
  truth. Run transfer-inclusive real
  capture → Vulkan → View → ROS consumer, ≥10 minutes, bounded slots, unique
  frames/drops/frame age, memory and GPU-sharing pressure. The p99 ≤15 ms GPU
  processing gate and 60 Hz delivered fresh metric-depth goal remain targets;
  report camera/USB age separately. Do not promote a speed-only winner.

Research references are sources of concepts, not a license to copy code or
weights: [ELAS](https://www.cvlibs.net/publications/Geiger2010ACCV.pdf) support
points and priors, [PatchMatch Stereo](https://www.microsoft.com/en-us/research/publication/patchmatch-stereo-stereo-matching-with-slanted-support-windows/)
slanted-plane propagation, and [HITNet](https://openaccess.thecvf.com/content/CVPR2021/html/Tankovich_HITNet_Hierarchical_Iterative_Tile_Refinement_Network_for_Real-time_Stereo_Matching_CVPR_2021_paper.html)
and [StereoNet](https://openaccess.thecvf.com/content_ECCV_2018/html/Sameh_Khamis_StereoNet_Guided_Hierarchical_ECCV_2018_paper.html)
hierarchical refinement. HITNet and StereoNet are neural methods; their reported
performance does not predict the classical Vulkan prototype. Review licenses and
attribution separately before reusing any implementation, model or dataset.
