# Fast60 quality-first benchmark and refinement implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development. Supervisor owns GPU dispatch, integration and publication. Preserve dirty implementation checkout and other agents' files.

**Goal:** Establish independently measured quality against executed ZED SDK references, then reach stable native 720p metric-depth processing at 60 Hz without hiding quality loss or historical reuse.

**Architecture:** Keep full-resolution original camera RGB and independent two-eye SGM as the internal baseline. The multiresolution matrix and guided refinement are now experimental evidence, not a selected replacement. Next build canonical SDK export/replay and an already-rectified native adapter, establish full-SGM quality on common frames against independent truth, then compare Fast60 and optimize recovered geometry at a frozen quality target. Compact adaptive matching and portable neural inference remain separately qualified experiments.

**Tech stack:** C++20, pinned Daxa/Slang/Vulkan; Python/OpenCV only for offline calibration/fixtures/evaluation. No CUDA/HIP/ROCm/TensorRT production dependencies.

**Spec:** User's 2026-10-28 SDK comparison amendment captured in [the quality benchmark design](../specs/2026-10-28-zed-quality-benchmark-design.md), the existing Fast60 strategy and parent `2026-10-27-daxa-slang-production.md`; temporal contracts in `../specs/2026-10-28-native-temporal-design.md` remain binding.

## Current decision and next priority

The [refinement evidence](../../fast60-refinement-evidence.md) reports roughly
54.4% correct metric completeness for guided matching versus 95.3% for full SGM
on the same analytic scene. Approximately 8 ms exploratory combined GPU time
does not compensate for that loss. Confidence-floor development ablation reaches
about 69.1% overall but only about 0.52% thin completeness; threshold relaxation
is not a quality fix. Native correctness, independent physical accuracy and live
60 Hz remain separate gates.

**Next execution order:** common record/export contract → isolated SDK runner →
native common-input adapter → full-SGM/SDK independent quality baseline → Fast60
quality diagnosis/refinement → frozen held-out evaluation → sustained/ROS output.
Follow the [benchmark implementation plan](2026-10-28-zed-quality-benchmark.md).
Existing completed experiments below retain their evidence; this amendment
supersedes their previous optimization priority. SDK host availability cannot
block portable contract/evaluator work, but missing SDK runs cannot pass parity.

## Frozen boundaries

- Profiles: rectified1280×720/D128,960×540/D96,640×360/D64, independent Left AND Right, four paths, matched penalties/subpixel/wave32. Original capture bytes/calibration/source RGB remain unchanged. No derived-right promotion.
- Native D96 is admitted already (StereoConfig1…256, dynamic specialized packed shader); qualify it rather than change kernels or silently substitute D128. Existing Python qualification whitelists need explicit tests/extensions.
- Freeze LR tolerance at1pixel and stereo schedule `sequential` for the primary matrix; four independent-reference paths, p1=8/p2=32, subpixel enabled, wave32. Changes require a separately labelled ablation.
- Scale focal lengths and principal-point offsets consistently. Use pixel-centre convention `u_small+0.5=s*(u_full+0.5)`, so `fx'=s*fx`, `cx'=s*(cx+0.5)-0.5` (and y equivalents). Scale projection Tx and disparity offset; preserve metric baseline and original camera models/R1/R2. Reject incompatible aspect/shape choices.
- Recompute maps directly from original calibrated models into the requested rectified grid. Do not rescale already rectified RGB or discard original peripheral colour. Preserve original source dimensions/stride/timestamps and map/model association gates. Existing bilinear remap is the initial measured sampling profile; antialiasing/texture loss is a quality question, not assumed solved.
- Equivalent approximate minimum metric distance follows `Z=fx*b/(d-(cxL-cxR))`; report calibrated profile limits using nominal near `fx*b/((D-1)-cx_offset)` only when that denominator is positive (otherwise unavailable). D128/D96/D64 scaled profiles have approximately, not exactly, equal near range because their integer maximum disparities differ. Never claim D64 full-resolution preserves D128 near-field range. Do not use representative camera focal lengths as actual fixture calibration.
- Primary stereo comparison disables RGB synthesis and temporal guidance. Measure full-resolution output/View cost separately with an explicitly fixed virtual camera, not a silently shrunken output canvas.
- Reduced-resolution depth remains labelled as such. Upsampling does not create independent full-resolution measurements. Strict geometry, validity/confidence/source IDs and observation ages retain their existing meanings.
- Desired processing gate: p99≤15ms with maximum service time, raw samples and frame-age/throughput/queue/drop accounting. Stage budgets6ms coarse/3ms refinement/3ms metric+View plus1–2ms overhead are targets, not predictions or measurements.
- Final live gate: ≥10minutes nominal60Hz, delivered unique frames/gaps/drops/age/queue growth, bounded2–3 slots, actual capture→GPU→consumer with relevant sharing pressure. Camera transport/exposure age is separate from processing service time.
- External SDK reference work is isolated on supported NVIDIA/Ubuntu; its proprietary/CUDA dependencies are not StereoForge runtime dependencies. Record supported modes, installed versions, effective calibration and any fallback. Primary external target is executed `NEURAL_LIGHT`; `NEURAL`/`NEURAL_PLUS` are additional profiles and deprecated `PERFORMANCE` is an availability-checked classical control.
- Preserve raw confidence conventions and separate matching/texture filtering. Compare error-versus-coverage, not equal numeric thresholds. Primary instantaneous quality has temporal stabilization off; temporal-on tests are separate.
- D128 is not the full nominal ZED 2 near-field envelope. Report calibrated supported range and requested0.3–8m completeness separately; shifted/local searches beyond128 are explicit experiments, not silently global D256 or removed truth samples.

## Review focus

- Half-pixel scaling, P2 Tx/cx offsets and original-vs-rectified identity must preserve metric geometry.
- Thin objects/discontinuities and near depth may disappear at coarse resolution; completeness and false accepts must accompany error metrics.
- D96 packing tails and LR handling must match independent scalar/frozen control outputs before timing.
- Lower-grid support and sparse virtual splats must not become unmarked full-resolution depth or inflated coverage.
- Tile/adaptive refinement must reduce candidate AND aggregation work; masked dense recurrences are not a demonstrated saving.
