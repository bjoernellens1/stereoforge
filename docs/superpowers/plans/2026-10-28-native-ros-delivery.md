# Native ROS delivery and benchmark report implementation plan

> **For agentic workers:** Use superpowers:subagent-driven-development. Execution is already authorized; continue without an approval menu. This implements parent Task7 software and preserves its actual-run qualification gates.

**Goal:** Publish real native Vulkan depth/RGB through optional ROS2, account for unique subscriber deliveries and produce evidence-backed cross-track reports.

**Architecture:** One submission thread drives NativeCapture and persistent two-slot native producers/export. Two reusable ROS messages copy only requested outputs at the explicit CPU publication boundary. A separate bounded native subscriber records actual receipts. Offline Python joins versioned traces and reruns existing raw quality/timing evaluators, never treating publish calls or summary flags as delivered/qualified evidence.

**Tech Stack:** C++20/Daxa/Slang, optional ROS2 Jazzy rclcpp/sensor_msgs; offline Python evaluators. No ROS/CUDA/SDK in default builds.

**Spec:** [Task7](2026-10-28-zed-quality-benchmark.md#task-7-sustained-delivery-ros-2-and-final-report), [quality-first design](../specs/2026-10-28-zed-quality-benchmark-design.md), [native export prerequisite](../../native-host-export-evidence.md).

## Global constraints

- At least600s nominal60Hz, unique depth/RGB, drops/gaps/frame age/queue growth/memory; actual capture→GPU→consumer. RGB-only and fixed View costs separate. Static/replay cannot qualify live delivery.
- ROS depth is32FC1 axial-Z metres in the rectified-left optical frame; RGBA isrgba8. Capture stamp uses supplied bounded source→ROS system mapping; reject unknown clock, simulated time, overflow, changed source device/calibration and repeated/backward identity.
- Keep stereo, images and metadata GPU-resident between native stages. Only requested left depth/RGBA are copied out. Retain source through copy completion, destination through CPU message copy; keep producer graph owners alive throughout steady state.
- Publisher call, subscriber receipt, host-observed completion and GPU timestamp intervals are distinct. Do not call host observation a device timestamp or infer measurement FPS from GPU milliseconds.
- Exactly2 processing/export slots (preprocess limit), capture queue2/pool6, QoS keep_last/depth1/volatile with explicitly matched best_effort or reliable. No unbounded buffering, JSON/file I/O/full readback or application buffer allocation inside the native steady-state loop.
- SDK/topic/reference and physical/held-out accuracy gates remain separate. Missing policies, View, reference, source/clock bindings or subscriber evidence mean explicit unqualified results.

## Review focus

1. Duplicate source frames, historical output or duplicate subscriber headers must not increase unique fresh deliveries.
2. Completion/ROS header timestamps in incompatible clocks, source reset, clock-map expiry or simulation time must reject or remain unavailable, never produce invented latency.
3. Publisher/subscriber start/stop windows, drain, missing receipts and queue/memory snapshots must not hide dropped/in-flight work.
4. Ring/trace full, publish failure, source EOF/timeouts and exceptions must release completed leases safely, stop capture, and preserve bounded diagnostics.
5. Precomputed/fabricated qualification flags or mismatched methods/calibration/settings cannot promote final reports; rerun raw validators and bind profiles.

## Shared trace contract (tasks1/2)

Trace files are JSON arrays, emitted after the timed loop. `summarize_delivery(events, *, policy=None)` accepts concatenated role traces. Max2000000 events; no float timestamps. Integers ns0..INT64_MAX; text bounded4096B; roles publisher/subscriber. Every event has exactly `schema,kind,run_id,role,at_ns` plus its kind-specific fields. Schema=`stereoforge.ros_delivery_event.v1`; run_id stable nonempty, at_ns host steady clock. One start/stop per role/run; monotonic role order; multiple runs summarized separately, never pooled to satisfy600s.

Start fields: `config`. Publisher config exactly `clock_id,source_mode,nominal_hz,slots,capture_queue_capacity,outputs,qos,implementation,calibration_identity,effective_estimator,view_profile,clock_mapping,capture_counters,memory`. Subscriber config exactly `clock_id,nominal_hz,outputs,qos`. clock_id binds Linux boot_id + monotonic clock + time-namespace inode, shared only by comparable processes; different domains cannot yield middleware latency. source_mode=camera|replay|synthetic; nominal_hz>0<=120. outputs nonempty subset depth/rgb, each exactly `topic,width,height,step,encoding,frame_id`; units/layout checked with ROS contract (32FC1 or rgba8), unique topics. qos exactly `history,depth,reliability,durability` =keep_last,1,best_effort|reliable,volatile. implementation follows existing Availability-aware native method descriptor or unavailable with reason. calibration_identity SHA256. effective_estimator is explicit actual profile object, not user-loaded quality claims; missing profile keeps comparisons unqualified. view_profile Availability, missing remains unavailable. clock_mapping exact RosCaptureClockMapping fields. capture_counters exact native CaptureMetrics fields. memory exactly `producer_requested_bytes,export_requested_bytes,capture_requested_bytes,trace_capacity,trace_record_bytes,ros_requested_bytes,export_memory_type_index,export_memory_property_flags,export_host_cached,storage_accounting_complete`; integer fields are nonnegative and cached/coherent flags reflect the selected Vulkan type (not allocator/RSS/VRAM claims). Missing requested-buffer categories set storage_accounting_complete=false and cannot satisfy the memory gate.

Published fields: `output,source_id,capture_ns,capture_clock,host_ingress_ns,mapped_capture_ns,mapping_error_ns,producer_ticket,copy_ticket,producer_complete_observed_ns,copy_complete_observed_ns,copy_begin_ns,copy_end_ns,publish_begin_ns,publish_end_ns,capture_queue,pending,freshness`. source_id nonnegative int64; capture/mapped capture positive; freshness=`measured_single_source`|`historical`|`unknown`. at_ns=publish_end_ns; copy ticket>producer ticket; host-observed readiness<=copy_begin<=copy_end<=publish_begin<=publish_end. Source IDs may repeat across different output kinds of the same capture, never count repeated same-output identity twice. Known full independent SGM emits measured_single_source; no temporal estimator is wired silently.

Received fields: `output,mapped_capture_ns,arrival_system_ns,width,height,step,encoding,frame_id,payload_bytes`. at_ns=arrival steady clock; verify actual message shape/layout/header against start config, including exact bytes. Join to publications by run/output/header stamp/frame label; unmatched or conflicting observations remain visible and cannot qualify. Repeated arrivals count once. Publish-call-start→arrival interval is explicitly named and includes publish-call overhead; do not label it isolated DDS transmission latency.

Stop fields: `window_end_ns,reason,counters,capture_counters,queued,pending,trace_drops,drain_ns`. window_end>=start.at_ns and<=stop.at_ns; measured events selected by start<=at<=window_end; later drain events counted separately. counters exactly `read,admitted,ring_drops,identity_rejects,published_depth,published_rgb,received_depth,received_rgb,timeouts`; nonapplicable role counters zero. Publisher capture_counters native snapshot; subscriber null. Native counters are cumulative delta from start; stop capture snapshot is window-end snapshot, not an after-drain replacement. queued/pending window-end values, bounded by configured capacities. EOF/limits/shutdown/error/trace_full explicit reasons. Counters never imply receipts.

Delivery policy optional strict object: `schema,frozen,min_duration_s,target_hz,min_delivery_hz,max_drop_fraction,max_gap_ms,max_frame_age_ms,max_clock_error_ns,max_queue_growth,max_requested_bytes`; schema=`stereoforge.ros_delivery_policy.v1`. Defaults are unavailable, not passing thresholds; validate min_duration>=600,target_hz=60, finite nonnegative bounds, min_delivery_hz<=target, fractions0..1. Only frozen policy may qualify. Config nominal_hz must match target, source camera, complete matching publisher+subscriber outputs/QoS and same clock, known mapping; all required outputs meet thresholds individually. Clock/age unavailable is not zero. Unique delivery rate = fresh received count / measured overlap duration; arrival gaps p50/p95/p99/max use actual ordered unique arrivals, not count-derived percentiles. Completeness/drop denominator explicit offered source delta and per-output admitted/published/received counts; dedup/safe reset preserve fixed support. No quality/SDK parity claim from this function.

**Owner/files:** native worker owns `apps/ros2_depth_publisher.cpp`, `apps/ros2_delivery_probe.cpp`, `include/stereoforge/ros_delivery_trace.hpp`, `tests/ros_delivery_trace.cpp`, `tests/test_ros_delivery_trace.py`, `tests/test_ros_publication_hotpath.py`. Native trace structs hold fixed POD entries in one pre-reserved bounded vector; setup strings and post-loop JSON conversion only. Shared header clock/image contract checks and serialization actual-source CPU tested without ROS SDK or fake production GPU.

Publisher CLI: `--source camera|replay --manifest FILE [--replay DIR] --mode depth|rgb|depth-rgb --fps60 --duration-seconds S --max-frames N --warmup N --clock-map FILE --optical-frame ID --depth-topic NAME --rgb-topic NAME --trace FILE --run-id ID [--validation] [--reliability best_effort|reliable]`. Strict bounds duration(0,3600], max_frames1..200000, warmup0..30; defaults600s,100000frames,5warmup, at most400002 trace events, sized from the configured frame/output bound. Slots fixed2, capture queue2/pool6, default capture/read timeout100ms. Existing output paths reject; source/replay options mutually consistent. Use source-specific actual metadata, not the fixture's retained ordinal. Mapfile is5-field RosCaptureClockMapping JSON. use_sim_time rejects before capture/GPU; NodeOptions intra_process_comms false. Linux little endian required. D128/four-path independent SGM, p1=8,p2=32, subpixel=true, lr_tolerance1, raw map geometry from real loader; no historical inference. RGB-only uses preprocess+export and never constructs stereo. Keep default producers alive. First actual capture must match supplied bundle device/calibration/geometry; compare every admitted source against bound device/clock/geometry. Setup prototypes and warmup excluded; zero output subscribers is allowed but cannot prove delivery. Keep original RGB GPU resources, export only requested rectified-left output.

Native loop retires ready pending slots before reading, never waits GPU implicitly to admit, drops newly read frame if both slots occupied before GPU enqueue, checks monotonic FreshSourceTracker and mapping before enqueue. Poll copy ready; query producer/copy observed readiness on same host steady clock. CPU memcpy into pre-sized Image, then publish(const&) with intra-process disabled. Measure copy and publish-call start/end separately; no per-frame file/JSON/full readback. Bounded trace full stops with explicit trace_drops and reason; do not silently wrap telemetry. At limit sample window end/counters/queue before capture.stop and explicit drain. Trace later drain publication separately by timestamp. Errors stop capture and drain safely; no fabricated normal-success result. Native frame/provenance knows raw independent SGM; do not assign freshness to future temporal output.

Probe CLI: matching run/topics/encoding/resolution/optical frame/QoS plus duration/maxframes/trace. No Daxa dependency for probe. Actual sensor_msgs::msg::Image subscription callbacks record arrival steady/system times and real headers/extent without copying pixels; reject inconsistent shape/layout. Single-thread executor, fixed reserved trace; no per-callback JSON/I/O. Start before publisher for discovery; no synthetic messages substituted. Store proper start/stop counters and endpoint window.
