# StereoForge v9.3 — planar recovery experiment contract

This branch adds an **offline CPU reference**, not an enabled depth feature. Its
purpose is to establish geometric and provenance contracts before adding a
Slang/Daxa GPU pass. **Do not merge as a completed 60 Hz/240 FPS milestone.**

## Current implementation

- File: `benchmarks/planar_recovery_v93.py`.
- CLI: `benchmarks/run_planar_recovery_v93.py` accepts an exact-grid NPZ.
- Tests: `tests/test_planar_recovery_v93.py`.
- Provenance is `0` unknown, `1` directly measured, `2` inferred from a plane.
- Direct disparity values and validity are preserved bit-for-bit; inferred
  disparities go only into a separate combined output, with provenance and
  confidence. Nothing is published to ROS.
- Affine 3×3 coarse disparity fit uses five or more coarse neighbors and a
  bounded residual. Inferred candidates require independent coarse left/right
  agreement, at least ten consistent direct anchors in a 41×41 window,
  anchors from three spatial quadrants, a full-resolution affine disparity fit,
  bounded fit residual, 5×5 mean-luma epipolar agreement, and an edge-gradient
  guard. Out-of-range values remain unknown.
- This CPU reference **does not yet evaluate the full-resolution five-tap
  descriptor at the *proposed* disparity**. That is a missing fifth guard
  before considering any GPU/ROS promotion. Photometric agreement alone
  must not be reported as independently verified depth correctness.

Input NPZ arrays: `measured_disp`, `measured_valid`, `coarse_left`,
`coarse_right`, `coarse_left_valid`, `coarse_right_valid`,
`rectified_left_gray`, `rectified_right_gray`. Disparities are in pixels
on their own grids; full resolution is exactly four times coarse resolution.
Use a genuinely independently estimated right disparity for reciprocal
qualification; a right disparity derived from left costs is correlated evidence.

```bash
python -m pytest -q tests/test_planar_recovery_v93.py
python -m benchmarks.run_planar_recovery_v93 \
  /path/to/desk_frame.npz \
  --output-prefix artifacts/v9_3_planar/desk_frame8 \
  --max-disparity 127
```

The output JSON contains pixel accounting, not independent depth-accuracy
metrics. The output NPZ contains the combined disparity, provenance mask,
inferred confidence, inferred mask, and coarse-plane prediction.

## Blockers before a production Slang port

1. Add a full-resolution matching descriptor **at the proposed disparity**.
   A low descriptor best cost at an unrelated winner is insufficient.
2. Recheck edge barriers with desk/table edges, nearby objects, glass,
   occlusion boundaries, and thin structures; require correct new geometry,
   not simply more filled pixels.
3. Verify independent ground truth or surveyed planar targets: inferred-only
   absolute bias, plane orientation, bad>1px and bad>2px, normal error,
   and false-free-space intrusion. Keep direct and inferred subsets separate.
4. Port into a *separate opt-in* Slang/Daxa pass with dedicated depth,
   confidence, and provenance buffers. Never overwrite
   `DaxaRefinementPlane::Depth/Validity/Provenance` or publish inferred
   values as measured by default.
5. Benchmark single-interval upload-to-completion p50/p95, inter-frame age,
   VRAM, and contention. The established processing budget is 4.167 ms,
   but the prototype has no measured GPU latency.
6. Fail qualification if synthetic or physical reference evidence is missing;
   do not reuse benchmark caches without an exact source/binary/shader digest.

## Independent Variant D causal ablation

Keep color matching out of `--selective-repair`. On identical recorded
stereo frames and identical candidate sets, compare:

- D-Y: add luminance penalty only for baseline tied minima;
- D-UV: add U/V penalty only for tied minima;
- D-YUV: combined selective brightness+chroma penalty;
- D-shuffled-UV: deliberately break cross-eye chroma alignment as a control.

Record new valid pixels, lost valid pixels, LR failures, direct-only accuracy,
temporal jitter, Q1–Q4 strata, and GPU cost. The earlier reported increase
of 9,473 valid pixels for D-YUV does **not** establish a chroma-specific
contribution: most recovered pixels occurred in low-chroma regions.

Only promote a color path if it adds independently correct pixels beyond the
cheapest luminance-only alternative. No color-matching change is included in
this branch.

## Scientific and implementation boundaries

This experimental module does not use reference depth, camera pose, or an
oracle mesh for prediction. Ground truth must be used only for evaluation.
The reference is a candidate-selection prototype, not a qualified GPU
implementation and not a substitute for StereoForge's measured depth.
